# テスト方針

- pytest を使う。設定は `pyproject.toml`（`src` を import パスに追加）。
- ロジックは、架空のポケモン数匹だけの `Converter` を使って、結果が一意に決まる形で検証する。
- 実データ（`data/pokemon.json`）を使うテストは、一致度の調整で結果が変わらないルール（候補の数、ポケモン側の音を省略しないこと など）だけにする。
- 「このフレーズならこのポケモンが出てほしい」という感覚の確認は、単体テストではなく正解例（`data/tuning_examples.json`）と
  `scripts/evaluate_scoring.py` で行う（development-guide.md の「一致度の調整」）。

| ファイル | 対象 |
|---|---|
| tests/test_kana.py | かな変換、モーラ分割、母音と子音の判定、ー の母音、省略しない設定の対応付け |
| tests/test_scoring.py | 1音の点数（母音・子音の近さ、ー・っ・ん、ー と子音のある音の減点）、一致度、枠ごとの減点、ー・っ の省略、ポケモン側を省略しないこと、末尾の余分な音 |
| tests/test_segmenter.py | 区切り、組合わせ候補と個別候補の数、1匹ごとの減点と弱い枠の減点、同点時の扱い、省略しない設定、枠内の候補が重ならないこと、序列ごとの重複除外 |
| tests/test_song.py | 入力チェック、フレーズID、重複モードとチャンネル、選択情報と手入力、省略しない設定、フレーズの変更、ロック、合体・分割、グループ、JSON の往復と version 1・2 の読み込み |

CLI（cli.py）は自動テストの対象外で、手動で動作を確認する。
