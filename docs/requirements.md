# 要件・仕様

ひらがなで入力したフレーズ（歌詞）を、音の近いポケモン名（1匹以上の組み合わせ）に変換する。
既存の曲の歌詞をポケモンの名前で歌えるようにすることが目的。現段階はコンソールアプリで変換ロジックを検証している。

## 用語
- **フレーズ**: 入力できるテキストの単位。
- **曲**: 複数のフレーズをまとめたもの。
- **音**: モーラ。拗音（しょ、でゅ 等）は1音、っ・ん・ー はそれぞれ1音。
  直前と同じ母音の小書き文字（ピィ、ケーシィ）は伸ばす音として独立した1音とする。
- **組合わせ候補**: フレーズの区切り方（例「4音 + 3音」）。
- **枠**: 区切った各区間。枠ごとに個別ポケモン候補を持つ。

## 入力
- フレーズはひらがなと「ー」で入力する。空白は取り除き、「～」「〜」「-」は「ー」として扱う。

## 音数の扱い
- フレーズとポケモンの音数は一致させる。ただし次の例外がある。
- **フレーズ側**の ー・っ は、あってもなくてもよい音として扱う（減点なし）。ん は常に1音として数える。
  - ユーザーが文字ごとに「省略しない」に設定した ー・っ は、必ず1音として数える（下の「省略しない設定」）。
  - だれもーが → 5音（プロトーガ）としても4音（サボネア）としても扱う
- **ポケモン側**の音は省略しない（でるぞ → ケムッソ は不可）。
  - 例外: フレーズ最後の枠のポケモンの最後の1音が ー・ッ・ン のときは、余分な1音として許す（減点なし）。
    ただし、フレーズの末尾が ー・っ・ん の場合は適用しない。
  - 例: たどりつくばしょ → スコルピ + クマシュン
- フレーズの ー・っ の位置からは区切らない（区間の先頭に ー・っ が来る区切りは作らない）。

## 一致度
1音ごとの点数を足し合わせて比べる。母音が合うことを最も重視する（母音が合えば歌ったときに近く聞こえるため）。

**1音の点数 = 母音の重み × 母音の近さ ＋ 子音の重み × 子音の近さ**（既定は 母音3・子音1。満点は4）

- 母音の近さ: 同じなら 1.0。違う場合は次の表の順に 0.4 / 0.3 / 0.15 / 0。

| フレーズ側の母音 | 1番目 | 2番目 | 3番目 | 4番目（0） |
|---|---|---|---|---|
| あ段 | え段 | い段 | う段 | お段 |
| い段 | え段 | あ段 | う段 | お段 |
| う段 | え段 | お段 | あ段 | い段 |
| え段 | あ段 | い段 | お段 | う段 |
| お段 | あ段 | う段 | え段 | い段 |

- 子音の近さ: 同じなら 1.0。清濁だけ違う（か/が、さ/ざ、た/だ、は/ば/ぱ）なら 0.6。
  似た音（ま/ば/ぱ、な/ら/だ 0.4、な/ま 0.3、や・わ と母音だけの音 0.4）。それ以外は 0。
- 「ー」は直前の音の母音だけの音として扱う（くー の ー は「う」と同じ音。きー の ー とは違う音）。
- 「っ」「ん」は、同じものどうしのときだけ満点。それ以外は 0。
- 片方が「ー」で、もう片方が子音のある音のときは、0.5点下げる（0点未満にはしない）。
  「ー」は前の音を伸ばす1つの音で、子音のある音は別々に発音する音なので、母音が同じでもリズムが少し違うため。
  「ー」と母音だけの音（くー の ー と う）は完全一致のまま。
- フレーズ側で省略した ー・っ は、1音あたり固定の点数（既定 2）を入れる。
- 末尾の余分な1音（ポケモン側の ー・ッ・ン）は、点数に関わらない。
- **一致度（％）** = 点数 ÷（音数 × 満点）。枠の候補ごと、組合わせ候補ごとに表示する。

### 組合わせ候補の比べ方
- 「各枠の第1候補の点数の合計 − 枠ごとの減点の合計」が高い順に並べる。枠ごとの減点は次の2つの合計。
  - 1匹ごとの減点（既定 1）。弱い短いポケモンで細かく区切るより、長く合うポケモンを優先するため。
  - 弱い枠の減点。枠の一致度が閾値（既定 65%）未満なら「係数（既定 1）×（閾値 − 一致度）× 音数 × 満点」。
    弱い枠が1つあると、平均の一致度が高くても全体が台無しに感じるため。
- 減点は順位付けにだけ使い、表示する一致度（％）には含めない。
- 同点なら匹数が少ない方、次に図鑑番号の順。

重み・減点などの値は `scoring.ScoringParams` にまとめてあり、`scripts/evaluate_scoring.py` と正解例
（`data/tuning_examples.json`）を使って調整する。

## 候補
- 1フレーズにつき組合わせ候補は最大2つで、一致度が高い順に並べる。
- 各枠の個別ポケモン候補は最大3匹（第1〜第3序列）。同じ枠の候補は、モードに関係なく必ず別のポケモンにする
  （別の枠どうしや、別の組合わせ候補どうしでは同じポケモンが出てもよい）。

## 選択情報
- 候補とは別に、ユーザーが決めたポケモンの並び（選択情報）をフレーズに持つ。一覧表示ではこの並びを表示する。
- 候補から1匹ずつ選んで末尾に追加する。組合わせ候補や枠をまたいで選んでよい
  （例: 組合わせ1の枠1の候補1、続けて組合わせ2の枠2の候補3）。
- 位置を指定して、別の候補や手入力のポケモンと入れ替えられる。削除・全消去もできる。同じポケモンを2回入れてもよい。
- 変換した直後は空。変換し直しても選択情報は残る。

## 手入力
- 選択情報に対して、一覧にあるポケモンを名前（カタカナ表記）または読み（ひらがな）で入力できる。
  末尾に追加するか、位置を指定して入れ替える。音数や一致度は問わない。
## 省略しない設定
- フレーズ内の ー・っ を、文字の位置（先頭から何文字目か）で指定して「省略しない」にできる。解除もできる。
- ー・っ 以外の位置は指定できない。ロック中でも設定できる（反映は変換し直したとき）。
- 合体では文字の位置をずらして、分割では前半・後半に振り分けて引き継ぐ。

## フレーズの変更
- 既存のフレーズの文字列を変更できる。入力チェックは追加のときと同じ。
- 変更すると、候補・選択情報・省略しない設定はリセットする。ID・チャンネル・グループは引き継ぐ。ロック中は変更できない。

## 重複禁止モードとチャンネル
- 重複を許すモードと許さないモードを曲全体で切り替えられる（既定は許すモード）。
- 各フレーズは重複チャンネル（1以上の整数。既定は 1）を持つ。
- 許さないモードでは、**同じチャンネルのフレーズどうし**で、**個別候補の同じ序列**に同じポケモンが出ないようにする。
  同じフレーズの別の組合わせ候補や、別の枠どうしでも同じ扱い。チャンネルが違えば重複してよい。
  - 例: どこかの枠の第1候補がマリルなら、同じチャンネルの他の枠の第1候補にはマリルを入れない（第2・第3候補なら可）。
  - 他のフレーズの選択情報（手入力を含む）にあるポケモンは、第1序列として扱う。
  - 全フレーズのチャンネルがバラバラなら、重複を許すモードと同じ動きになる。
- 許すモードでは、チャンネルは無視する。
- 一括変換はフレーズ順 → 組合わせ候補順 → 枠順に決める。対象外のフレーズ（ロック中など）の候補と選択情報は先に押さえる。
- 1フレーズだけ変換するときは、同じチャンネルの他のフレーズの現在の候補をすべて除外の対象にする。

## ロック
- フレーズの変換結果をロックできる。ロック中は変換・選択情報の変更（手入力を含む）・フレーズの変更・合体・分割ができない。
- 一括変換（曲全体／グループ）ではロック中のフレーズを飛ばす。チャンネルの変更はロック中でもできる。

## 合体・分割
- **合体**: 連続した2つ以上のフレーズを、歌詞の順のまま1つにする。
  選択情報は順につなげて引き継ぐ（同じポケモンが重なってもそのまま）。候補は消えるので、合体の後に変換し直す。
  チャンネルとグループは先頭のフレーズのものを引き継ぐ。
- **分割**: 先頭から何文字目の後ろで分けるかを指定して、必ず2つに分ける。拗音の途中では分けられない。
  分けた2つのフレーズは、どちらも候補と選択情報が消える。チャンネルとグループは分割元のものを引き継ぐ。

## グループ
- 複数のフレーズをまとめてグループにできる。1つのフレーズが入れるグループは1つまで。
- グループに対して、変換（メンバーを歌詞の順に）、チャンネルの設定、ロック／解除ができる。
- 解除するとグループだけが消え、フレーズは残る。メンバーが0になったグループは自動で消える。

## ポケモンの名前
- 図鑑の名前（species 単位）を使う。フォルム違い・リージョンフォーム・メガシンカ・ゲンシカイキは扱わない。
- 特殊な読み（data/reading_overrides.json）: ポリゴン２=ぽりごんつー、ポリゴンＺ=ぽりごんぜっと、
  ニドラン♂=にどらんおす、ニドラン♀=にどらんめす。「・」「：」は取り除く。

## データ
- PokeAPI の生データ: `data/raw/pokeapi/pokemon-species/{id}.json`（現在は手元のデータを配置。収集スクリプトは未作成）
- 一覧データ: `data/pokemon.json`（`scripts/build_pokemon_list.py` で生成）
- 曲データ: JSON で保存と読み込みができる（既定の保存先は `data/songs/`）
